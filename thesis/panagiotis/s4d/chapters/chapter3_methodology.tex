\chapter{The S\textsuperscript{4}D System}
\label{ch:s4d-system}

This chapter presents the complete S\textsuperscript{4}D (Style and Structure Similarity for Site Domains) system implementation, detailing the 7-step workflow from web page acquisition through similarity analysis to final result presentation. The system combines advanced web parsing, clustering algorithms, and multi-dimensional similarity computation to provide robust website comparison and categorization capabilities.

\section{System Overview}
\label{sec:system-overview}

The S\textsuperscript{4}D methodology employs a comprehensive multi-stage pipeline that transforms raw web pages into structured similarity matrices and clustering results. The system architecture consists of seven main processing components integrated within an 8-section organizational framework:

\begin{enumerate}
    \item \textbf{Web Page Acquisition and DOM Extraction} - Automated web page rendering and hierarchical DOM tree construction
    \item \textbf{Multi-Level CSS Property Analysis} - Comprehensive CSS attribute extraction and normalization across multiple DOM depth levels
    \item \textbf{Feature Engineering and Vector Representation} - Transformation of CSS properties into numerical vectors suitable for machine learning algorithms
    \item \textbf{Advanced Clustering Analysis} - HDBSCAN-based clustering with automatic parameter optimization and quality validation
    \item \textbf{Role Vector-based Similarity Computation} - Multi-dimensional similarity assessment using frequency, transition, and positional information
    \item \textbf{Multi-Metric Similarity Framework} - Combined similarity scoring using geometric mean of multiple distance metrics
    \item \textbf{Performance Optimization} - Efficient data structures and scalable processing architectures
\end{enumerate}

\section{Web Parsing (Levels + Clustering)}
\label{sec:web-parsing}

This section details the comprehensive web parsing implementation that combines automated DOM extraction with multi-level structural analysis (levels 1-10) and integrated clustering preparation for the subsequent HDBSCAN analysis phase.

\subsection{Automated Web Rendering}
\label{subsec:web-rendering}

The S\textsuperscript{4}D system employs Selenium WebDriver with Chrome browser in headless mode to ensure consistent web page rendering. The browser configuration includes:

\begin{itemize}
    \item \textbf{Headless Mode}: \texttt{--headless} flag eliminates GUI overhead and ensures reproducible rendering
    \item \textbf{Security Configuration}: \texttt{--no-sandbox} and \texttt{--disable-dev-shm-usage} flags enable execution in containerized environments
    \item \textbf{Performance Optimization}: \texttt{--disable-gpu} flag reduces resource consumption
    \item \textbf{Standardized Viewport}: Fixed window size of 1920×1080 pixels ensures consistent element positioning
\end{itemize}

\subsection{Hierarchical DOM Tree Construction}
\label{subsec:dom-construction}

The DOM extraction algorithm employs a recursive traversal strategy implemented through the \texttt{HTMLTag} class. Each web element is processed through the following steps:

\subsubsection{Unique Element Identification}
A sophisticated unique ID generation algorithm combines timestamps and random numbers to ensure element uniqueness:

\begin{equation}
\text{unique\_id} = \text{timestamp}_{ms} \times 10^{10} + \text{random}_{[10^9, 10^{10})}
\end{equation}

where \texttt{timestamp\_ms} represents milliseconds since epoch and \texttt{random} is a uniformly distributed random integer.

\subsubsection{Comprehensive Attribute Extraction}
The system extracts three categories of element information:

\begin{enumerate}
    \item \textbf{HTML Attributes}: Native element attributes obtained via JavaScript execution
    \item \textbf{Computed CSS Properties}: All computed style properties accessed through \texttt{window.getComputedStyle()}
    \item \textbf{Geometric Properties}: Element bounding rectangle coordinates obtained via \texttt{getBoundingClientRect()}
\end{enumerate}

\subsubsection{Text Content Processing}
Text extraction employs JavaScript-based DOM node traversal to isolate element-specific text content:

\begin{lstlisting}[caption=Text Content Extraction Algorithm]
let textContent = '';
for (let node of element.childNodes) {
    if (node.nodeType === Node.TEXT_NODE) {
        textContent += node.textContent;
    }
}
return textContent.trim();
\end{lstlisting}

Text content undergoes normalization through regular expression-based cleaning that preserves Unicode characters while removing non-printable ASCII characters.

\subsection{Multi-Level DOM Analysis}
\label{subsec:multi-level-analysis}

The S\textsuperscript{4}D system implements a bottom-up hierarchical analysis approach across 10 configurable levels (levels 1-10). The level system works from the leaf nodes of the DOM tree upward, where each level represents the path length from leaf elements toward the root:

\begin{itemize}
    \item \textbf{Level 1}: Leaf elements (bottom-most elements with no children)
    \item \textbf{Level 2}: Leaf elements plus their immediate parent elements
    \item \textbf{Level 3}: Leaf elements plus parent and grandparent elements
    \item \textbf{Levels 4-6}: Extended upward paths capturing intermediate structural relationships
    \item \textbf{Levels 7-10}: Complete structural hierarchies approaching root-level containers
\end{itemize}

This bottom-up approach ensures that the most content-specific elements are captured first, with increasing levels incorporating broader structural context. The exact structural granularity captured at each level varies depending on the specific DOM tree depth and organization of each website.

\subsection{CSS Property Analysis and Normalization}
\label{subsec:css-analysis}

\subsubsection{Attribute Filtering and Selection}
The system implements a sophisticated attribute filtering algorithm that identifies structurally significant CSS properties. The filtering process involves:

\textbf{Element Frequency Analysis}
For each CSS attribute, the system computes the distribution of elements across all analyzed websites:

\begin{equation}
\text{frequency}_{attr} = \frac{\text{elements\_with\_attr}}{\text{total\_elements}}
\end{equation}

\textbf{Useful Attribute Identification}
Attributes are classified as "useful" based on their discriminative power. The algorithm specifically focuses on:

\begin{itemize}
    \item \textbf{Typography Properties}: \texttt{font-size}, \texttt{font-weight}, \texttt{font-style}
    \item \textbf{Layout Properties}: \texttt{text-align}, \texttt{line-height}
    \item \textbf{Interaction Properties}: \texttt{cursor}, \texttt{word-break}
    \item \textbf{Decoration Properties}: \texttt{text-decoration-line}, \texttt{text-decoration-style}
\end{itemize}

\subsubsection{CSS Value Normalization}
The system implements comprehensive CSS value normalization to handle diverse value formats:

\textbf{Pixel Value Normalization}
Pixel values undergo standardized processing:

\begin{equation}
\text{normalized\_px} = \begin{cases}
-1 & \text{if value} = \text{"auto"} \\
-\frac{\text{percentage}}{100} & \text{if value contains "\%"} \\
\text{float(value.replace("px", ""))} & \text{otherwise}
\end{cases}
\end{equation}

\textbf{Color Space Processing}
RGB/RGBA color values are converted to HSV color space for perceptual similarity analysis:

\begin{align}
H &= \arctan2(\sqrt{3}(G-B), 2R-G-B) \\
S &= 1 - \frac{3\min(R,G,B)}{R+G+B} \\
V &= \frac{R+G+B}{3}
\end{align}

\textbf{Implementation}: The system uses Python's \texttt{colorsys.rgb\_to\_hsv()} function for color space conversion:

Properties with multiple coordinate values (e.g., margins, padding) undergo specialized processing:

\begin{equation}
\text{ordering} = \begin{cases}
(X, Y) & \text{if } X \geq Y \\
(-X, -Y) & \text{if } X < Y
\end{cases}
\end{equation}

\section{Data Modeling (Levels + Clustering)}
\label{sec:data-modeling}

The S\textsuperscript{4}D system employs sophisticated data modeling techniques to transform raw web page data into structured representations suitable for multi-level analysis and HDBSCAN clustering. This includes both pre-clustering data preparation across DOM levels 1-10 and post-clustering data enrichment with cluster assignments and metadata.

\subsection{Feature Engineering and Vector Representation}
\label{subsec:feature-engineering}

\subsubsection{Page Vector Construction}
The system constructs multi-dimensional feature vectors for each DOM element by processing useful CSS attributes. The vector construction algorithm:

\begin{enumerate}
    \item \textbf{Initializes} empty vectors for each unique element ID
    \item \textbf{Processes} each useful attribute sequentially
    \item \textbf{Appends} normalized attribute values to element vectors
    \item \textbf{Maintains} consistent vector dimensionality across all elements
\end{enumerate}

\subsubsection{String Value Space Mapping}
Non-numeric CSS values are mapped to numerical representations through a global string value space (\texttt{str\_VSM}):

\begin{equation}
\text{numerical\_value} = \text{index\_of\_string\_in\_VSM}
\end{equation}

Special handling is provided for framework-specific values (e.g., Bootstrap's "start" → "left", "end" → "right").

\subsubsection{Data Standardization and Normalization}
Feature vectors undergo standardization using scikit-learn's \texttt{StandardScaler}:

\begin{equation}
X_{\text{scaled}} = \frac{X - \mu}{\sigma}
\end{equation}

where $\mu$ represents the feature mean and $\sigma$ represents the feature standard deviation.

\label{subsec:pre-clustering-modeling}

Before clustering analysis, the system creates comprehensive data models:

\textbf{JSON Data Structures}

\textbf{Element-to-Property Relations}
\begin{itemize}

    \item \textbf{Geometric Information}: Bounding rectangles and positional data
    \item \textbf{Content Analysis}: Text content with size metrics and semantic information
\end{itemize}

\subsection{Vector Space Construction}
\label{subsec:vector-space-construction}

The system constructs multi-dimensional feature vectors for machine learning processing:

\textbf{Feature Vector Components}
\begin{itemize}
    \item \textbf{Normalized CSS Values}: Pixel values, percentages, and categorical properties
    \item \textbf{Color Space Representations}: RGB to HSV conversions for perceptual similarity
    \item \textbf{Positional Encoding}: Relative positions within DOM hierarchy
\end{itemize}

\subsection{Vectorization and HDBSCAN Clustering Integration}
\label{subsec:clustering-integration}

\textbf{Step 3: Vectorizing and Clustering Web Elements}

The data modeling phase seamlessly integrates with the HDBSCAN clustering algorithm to transform feature vectors into meaningful element groupings using density-based clustering with DBCV validation.

\subsubsection{HDBSCAN Parameter Optimization}
The system implements a grid search optimization strategy across multiple parameter combinations:

\begin{itemize}
    \item \textbf{Cluster Size Range}: Dynamic range from 5 to 10\% of total elements
    \item \textbf{Selection Epsilon}: Range from 0.0 to 1.0 with 0.333 step increments  
    \item \textbf{DBCV Threshold}: Early stopping at scores below 0.25
    \item \textbf{Quality Selection}: Chooses configuration with fewest clusters among DBCV > 0.5
\end{itemize}

\subsubsection{Intelligent Outlier Reassignment}
The system implements a novel outlier reassignment strategy:

\begin{enumerate}
    \item Identify outliers (elements with cluster label = -1)
    \item Compute cluster centroids excluding outliers
    \item Calculate Euclidean distances from outliers to centroids
    \item Assign outliers to nearest cluster centroids
    \item Recompute centroids and repeat until convergence
\end{enumerate}

\section{Data Mining}
\label{sec:data-mining}

\textbf{Step 5: Transition Matrix Construction and Role Vector Extraction}

This section describes the data mining phase that transforms clustered elements into role vectors through transition matrix analysis and positional statistics computation.

\subsection{Transition Matrix Construction}
\label{subsec:transition-matrix}

The system constructs comprehensive transition matrices to capture sequential relationships between clusters within DOM structures:

\textbf{Algorithm Implementation}
\begin{enumerate}
    \item \textbf{Sequence Extraction}: Extract cluster ID sequences for each processed page
    \item \textbf{Transition Counting}: Count bidirectional transitions between adjacent clusters
    \item \textbf{Matrix Construction}: Build square matrices with dimensions equal to the number of unique clusters
    \item \textbf{Normalization}: Convert raw counts to probability distributions
\end{enumerate}

\textbf{Transition Probability Calculation}
For clusters $i$ and $j$, the transition probability is:

\begin{equation}
T_{i \rightarrow j} = \frac{\text{count}(i \rightarrow j)}{\sum_{k} \text{count}(i \rightarrow k)}
\end{equation}

\subsection{Cluster Positional Statistics}
\label{subsec:positional-statistics}

The system computes comprehensive positional statistics for each cluster to capture spatial distribution patterns:

\textbf{Position Normalization}
Raw positions are normalized to ensure comparability across different page structures:

\begin{equation}
\text{normalized\_pos} = \frac{\text{position}}{\max(\text{sequence\_length} - 1, 1)}
\end{equation}

\textbf{Statistical Measures}
For each cluster, the system computes:

\begin{align}
\mu_{pos} &= \frac{1}{n} \sum_{i=1}^{n} \text{pos}_{i,normalized} \\
\sigma_{pos} &= \sqrt{\frac{1}{n} \sum_{i=1}^{n} (\text{pos}_{i,normalized} - \mu_{pos})^2} \\
\min_{pos} &= \min(\text{normalized\_positions}) \\
\max_{pos} &= \max(\text{normalized\_positions})
\end{align}

\subsection{Role Vector Construction}
\label{subsec:role-vector-construction}

The system constructs comprehensive role vectors combining frequency, transition, and positional information:

\textbf{Complete Role Vector Specification}
Each cluster's role vector contains:

\begin{equation}
\mathbf{R}_{cluster} = [\text{freq}, \mathbf{T}_{out}, \mathbf{T}_{in}, \mu_{pos}, \sigma_{pos}, \min_{pos}, \max_{pos}]
\end{equation}

where:
\begin{itemize}
    \item $\text{freq}$: Cluster occurrence frequency
    \item $\mathbf{T}_{out}$: Outgoing transition probability vector
    \item $\mathbf{T}_{in}$: Incoming transition probability vector  
    \item $\mu_{pos}, \sigma_{pos}, \min_{pos}, \max_{pos}$: Positional statistics
\end{itemize}

\textbf{Frequency Calculation}
The cluster frequency represents relative occurrence across all elements:

\begin{equation}
\text{frequency}_{cluster} = \frac{\text{occurrences}_{cluster}}{\text{total\_elements}}
\end{equation}

\section{Similarity Analysis}
\label{sec:similarity-analysis}

\textbf{Step 6: Multi-Metric Similarity Computation}

This section describes the comprehensive similarity analysis framework that combines multiple distance metrics to produce robust similarity assessments between website domains.

\subsection{Multi-Dimensional Role Vector Construction}
\label{subsec:role-vectors}

The S\textsuperscript{4}D system constructs comprehensive role vectors for each cluster incorporating:

\subsubsection{Frequency Information}
Cluster occurrence frequency across website elements:

\begin{equation}
\text{frequency}_{cluster} = \frac{\text{occurrences}_{cluster}}{\text{total\_elements}}
\end{equation}

\subsubsection{Transition Matrices}
Bi-directional transition probabilities between clusters:

\begin{equation}
T_{ij} = \text{count}(\text{cluster}_i \rightarrow \text{cluster}_j)
\end{equation}

\subsubsection{Positional Statistics}
Statistical measures of cluster positions within DOM structures:

\begin{align}
\text{mean\_pos} &= \frac{1}{n} \sum_{i=1}^{n} \frac{\text{position}_i}{\max(\text{sequence\_length} - 1, 1)} \\
\text{std\_pos} &= \sqrt{\frac{1}{n} \sum_{i=1}^{n} (\text{normalized\_pos}_i - \text{mean\_pos})^2} \\
\text{min\_pos} &= \min(\text{normalized\_positions}) \\
\text{max\_pos} &= \max(\text{normalized\_positions})
\end{align}

\subsection{Complete Role Vector Specification}
\label{subsec:complete-role-vector}

The complete role vector for each cluster includes:

\begin{equation}
\mathbf{R}_{cluster} = [\text{freq}, \mathbf{T}_{out}, \mathbf{T}_{in}, \text{mean\_pos}, \text{std\_pos}, \text{min\_pos}, \text{max\_pos}]
\end{equation}

where $\mathbf{T}_{out}$ and $\mathbf{T}_{in}$ represent outgoing and incoming transition vectors.



\subsection{Best Setting Extraction}
\label{subsec:best-setting-extraction}

\textbf{Best Setting Extraction: Median Number of Clusters + Best DBCV Score}

The system implements a sophisticated algorithm to identify optimal clustering configurations through a combination of median cluster count analysis and DBCV score optimization:

\subsubsection{Median-Based Cluster Selection}
The system uses median cluster count as a stability criterion:

\begin{enumerate}
    \item \textbf{Valid Result Filtering}: Extract clustering results with clusters > 0 and DBCV > 0
    \item \textbf{Cluster Count Collection}: Gather cluster counts from all valid configurations
    \item \textbf{Median Computation}: Calculate median cluster count across all results
    \item \textbf{Configuration Ranking}: Order configurations by proximity to median cluster count
    \item \textbf{Quality Selection}: Among configurations near median, select highest DBCV score
\end{enumerate}

\subsubsection{DBCV Score Optimization}
The best configuration combines stability (median clusters) with quality (DBCV score):

\begin{equation}
\text{Best Config} = \arg\max_{\text{config}} \text{DBCV}(\text{config}) \text{ s.t. } |\text{clusters}(\text{config}) - \text{median}| \leq \tau
\end{equation}

where $\tau$ is a tolerance parameter for cluster count deviation from median.

\subsection{Extended Similarity Analysis Framework}
\label{subsec:more-similarity}

\subsubsection{Domain-Level Aggregation}
The system performs domain-level analysis by:

\begin{enumerate}
    \item \textbf{Grouping} websites by domain using URL parsing
    \item \textbf{Averaging} role vectors within domains
    \item \textbf{Computing} domain-representative vectors
\end{enumerate}

\subsubsection{Multi-Metric Distance Computation}
The system computes three complementary similarity metrics:

\textbf{Cosine Similarity}
Standard cosine similarity between domain average vectors:

\begin{equation}
\text{sim}_{cosine}(A,B) = \frac{\mathbf{A} \cdot \mathbf{B}}{|\mathbf{A}||\mathbf{B}|}
\end{equation}

\textbf{Implementation}: Uses scikit-learn's \texttt{cosine\_similarity()} function:

\begin{tcolorbox}[
    colback=gray!5!white,
    colframe=gray!60!black,
    title=\textbf{Cosine Similarity Computation},
    fonttitle=\bfseries,
    enhanced,
    arc=2mm,
    boxrule=0.5pt
]
\begin{lstlisting}[language=Python]
from sklearn.metrics.pairwise import cosine_similarity

# Compute cosine similarity between domain vectors
cosine_sim = cosine_similarity(domain_vectors)
\end{lstlisting}
\end{tcolorbox}

\textbf{Earth Mover's Distance (EMD) Approximation}
Bidirectional minimum distance computation:

\begin{equation}
\text{sim}_{EMD}(A,B) = \frac{1}{2}\left[(1 - \text{mean}(\min(\text{dist}(A,B)))) + (1 - \text{mean}(\min(\text{dist}(B,A))))\right]
\end{equation}

    colback=gray!5!white,
    colframe=gray!60!black,
    title=\textbf{EMD Distance Computation},

\textbf{Hausdorff Distance Approximation}
Maximum minimum distance computation:

\begin{equation}
\text{sim}_{Hausdorff}(A,B) = \frac{1}{2}\left[(1 - \max(\min(\text{dist}(A,B)))) + (1 - \max(\min(\text{dist}(B,A))))\right]
\end{equation}

\subsection{Best Level Selection Algorithm}
\label{subsec:best-level-selection}

\subsubsection{Median-Based Selection Strategy}
The system implements a sophisticated algorithm to identify optimal clustering levels:

\begin{algorithm}[H]
\caption{Best Clustering Level Selection}
\KwIn{clustering\_results: List of clustering result dictionaries}
\KwOut{best\_result: Clustering result with optimal configuration}
\Begin{
    valid\_results $\leftarrow$ filter clustering results with clusters > 0 and DBCV > 0\;
    \If{len(valid\_results) < 2}{
        \Return None\;
    }
    cluster\_counts $\leftarrow$ extract cluster counts from valid results\;
    median\_clusters $\leftarrow$ compute median of cluster counts\;
    ordered\_results $\leftarrow$ sort results by cluster count (ascending)\;
    Y $\leftarrow$ median position in ordered results\;
    W $\leftarrow$ cluster count at position Y\;
    filtered\_results $\leftarrow$ results with cluster count $\leq$ W\;
    \Return result with highest DBCV score from filtered results\;
}
\end{algorithm}

This approach balances clustering quality (DBCV score) with interpretability (fewer clusters), providing robust level selection across diverse website collections.

\textbf{Implementation}: The median-based selection algorithm is implemented as follows:

    colback=gray!5!white,
    colframe=gray!60!black,

]

def find_best_clustering_level(clustering_results):
    # Filter valid results (clusters > 0 and DBCV > 0)
    valid_results = [r for r in clustering_results 
                    if r.get('cluster_info', {}).get('num_clusters', 0) > 0 
                    and r.get('cluster_info', {}).get('dbcv_score', 0) > 0]
    
    if len(valid_results) < 2:
        return None
    
    # Extract cluster counts and find median
    cluster_counts = [r['cluster_info']['num_clusters'] for r in valid_results]
    median_clusters = np.median(cluster_counts)
    
    # Sort by cluster count and find median position
    valid_results.sort(key=lambda x: x['cluster_info']['num_clusters'])
    median_position = len(valid_results) // 2
    w_cluster_count = valid_results[median_position]['cluster_info']['num_clusters']
    
    # Filter results with W clusters or fewer
    filtered_results = [r for r in valid_results 
                       if r['cluster_info']['num_clusters'] <= w_cluster_count]
    
    # Return result with highest DBCV score
    if filtered_results:
        return max(filtered_results, key=lambda x: x['cluster_info']['dbcv_score'])
    
    return None
\end{lstlisting}
\end{tcolorbox}
